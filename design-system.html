Composite overlays

Figma variables cannot express Tailwind's /30 opacity modifiers, so the kit bakes the transparency into flat fills instead. In code you can usually delete these and use the modifier directly. Checkerboard shows through where the fill is partly transparent.

04

Elevation

Three shadows carry the whole kit. Figma stores them as multi-layer effect variables with every offset, blur and spread broken out as its own token, which is why the source names read so strangely.

shadow-xs
0 1px 2px 0 · black 5%
shadow-sm
0 1px 3px 0 · black 10%
0 1px 2px -1px · black 10%
shadow-lg
0 10px 15px -3px · black 10%
0 4px 6px -4px · black 10%

Those values are tuned for a white ground. Dark mode on this page deepens them, because a 10% black shadow does nothing on #0d1b2a. The deepening is a judgement call, not an extracted value.

11

Adopting it

You do not need to extract the components. The Figma kit tracks shadcn/ui 3.6+ closely enough that the components already exist as code you can install. What is bespoke here is the theme, and the theme is one file.

  1. Install shadcn/ui in the target project. Nothing about the setup changes. Take the components as they ship.
  2. Swap in the extracted globals.css. It carries 32 colour tokens per mode plus the radius, type and shadow scales. This is the whole handover.
  3. Load the two typefaces. Add Plus Jakarta Sans and IBM Plex Mono through your font loader. The --font-sans and --font-mono variables already point at them by name, so nothing else needs touching.
  4. Decide on the retuned type scale. Keeping it matches Figma exactly. Deleting the --text-* block restores Tailwind's defaults, which is safer if the project shares components with anything else.
  5. Fill the chart colours from section 10 before you ship a chart. That group is still entirely guessed. The navigation is specified, so the shell in section 06 is safe to build against now.
  6. Keep globals.css as the single source of truth. When the Figma theme moves, re-export and replace that one file rather than editing component code. That is what keeps design and build from drifting apart.

What the file looks like

Abridged. The real file carries every token in section 01.
:root {
  --radius: 0.625rem;
  --background: #ffffff;
  --foreground: #262626;
  --primary: #007a55;
  --border: #e8e8e3;
  --font-sans: "Plus Jakarta Sans", ui-sans-serif, system-ui, sans-serif;
}

.dark {
  --background: #0d1b2a;
  --foreground: #fafafa;
  --primary: #007a55;
  --border: #1d2b38;
}
On hex rather than OKLCH. Stock shadcn ships OKLCH. Figma has no OKLCH support, so the kit stores hex and this extraction preserves it. You can convert to OKLCH later without losing anything, since every hex has an exact OKLCH equivalent. Going the other way is where colours shift, so hex is the safer thing to hold as the source of truth.
